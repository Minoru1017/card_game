港灣訓練場 — 遊戲介紹

類型：Unity 回合制卡牌對戰 · 單機冒險 · Android 橫向
定位：畢業專題 playable demo — 主線 1-1／1-2、港灣訓練、組牌、鬥鳥暖身、批次平衡工具
撰寫思路：參考 UE5 作品集與履歷：HR 只看了 5 秒 — 不只展示「做了什麼」，而是說清楚 解決了什麼問題、怎麼做、結果如何。

一句話

這不是「照教程複刻的卡牌 UI」，而是一套 用 C# 把「新手能玩懂」與「數值可驗證」同時做出來 的 Unity 專題：
玩家在學院被帶打第一場，畢業後到港灣自己練；開發端則用批次模擬與 Editor 工具，把平衡與產能問題變成可量測、可重跑的工作流。

這是一款什麼遊戲？（30 秒版）
玩法 雙方英雄 20 HP，起手 5 張，場上怪獸對砍＋火球／治療／凝視等法術
成長 同一張怪物牌越打越熟，戰技分 A→B→C 階解鎖
關卡 1-1 學院入門 → 港灣實戰（簡單／普通／困難）→ 1-2 段考雙階段
平台 Android APK（橫向 1920×1080 基準）＋ Unity Editor 開發試玩
一局 約 5～15 分鐘

世界觀一句：你是學院新生，林可姐在舊校舍對戰館帶你學規則；畢業後大地圖的港灣訓練場，才是你要自己闖的實戰區。

這份專案解決了什麼問題？

以下依「問題 → 方案 → 結果 → 證據」整理，對應作品集／口試最常被問的：你為什麼這樣設計？有沒有數據或工具支撐？

1. 卡牌遊戲規則堆疊太快，新手第一局就放棄

問題
回合制卡牌常同時丟出：手牌上限、場上單位、法術條件、天氣、敵 AI、牌組構築。若第一場就全開，玩家記不住規則，只記得「怎麼突然就輸了」。

方案
- 分階開放：1-1 入門教學戰關閉整場天氣（IsWeatherSystemEnabledForBattle()），只練出牌、攻擊、結束回合。
- 劇情承載教學：Main Plot 帶進對戰館，教學戰接在劇情後，不強迫跳過敘事。
- 教練 UI：入門／港灣分開的 coach 模組，在關鍵時刻給戰術提示，而非事後查 wiki。
- 敵方意圖可讀：HUD 與教練提示讓「對手下一步想幹嘛」可見，降低資訊不對稱带来的挫折。

結果
- 入門流程目標 5～8 分鐘 完成第一場可理解對戰（企劃定案 LEVEL_DESIGN_GDD.md）。
- 玩家先建立「我看得懂盤面」的信心，再進港灣三檔難度與天氣系統。

證據
- 關卡流程：LEVEL_DESIGN_GDD.md §二（學院入門 vs 港灣實戰兩階段不可混）
- 程式：BattleSimulationManager、TutorialHandPlayAdvisor、HarborCombatCoachUi
- 畫面：Docs/pitch_pillar01_battle_hud.png

2. 「突然就輸了」— 資訊揭露與難度必須分檔設計

問題
若敵方強度與資訊量一次拉滿，玩家無法學習「為什麼這回合該擋／該攻」；難度若只靠感覺調 HP，口試時也無法回答「普通檔首通率多少」。

方案
- 五檔離散難度（入門～魔王）：牌組強度、法術比例、資訊揭露率、AI 風格（Greedy／Scheming）分開映射（DifficultyDesignProfile + SceneLoader.BuildDifficultyConfig()）。
- 港灣專用子規則：簡單檔第 10 回合限時必勝、敵傷害倍率分檔等，與入門教學數值解耦。
- 致死預警演出：敵方致死火球／攻擊前可播「You will die」提示（批次模擬時自動略過，不拖慢工具）。

結果
- 企劃 KPI：港灣簡單首通約 70%、平均約 10 回合內結束；普通首通目標約 60%（見 HarborTrainingEasyBattleRules、模擬報告）。
- 口試可明確說：本專案不做即時動態難度（DDA），而是戰前選檔 + 可重現的敵牌組。

證據
- 設計說明：DIFFICULTY_AND_AI_DESIGN.md
- 敵 AI 決策樹：ENEMY_AI_DECISION_TREE.md
- 港灣 1-1 vs 訓練場對照：HARBOR_1-1_VS_TRAINING_GROUND_DIFFICULTY.md

3. 數值平衡不能靠「我覺得好像可以了」— 需要批次模擬

問題
卡牌對戰狀態空間大，改一個敵傷害倍率或抽牌節奏，真人試 3 局看不出趨勢；若沒工具，畢業展示只能說「我調過 Inspector」。

方案
- BattleAutoSimPlugin + 批次 Bootstrap：Editor／命令列一鍵跑 N 局，統計勝／負／平。
- 港灣普通勝率模擬：HarborNormalWinRateSimBootstrap，200 局、固定種子、報告寫入 Assets/SimResults/。
- M-1-2 段考 A 模擬：除勝率外，另統計 段考通過率（勝利 + 御三家戰技皆觸發），對齊關卡通關條件而非只看 W/L。
- 第 12 回合上限、敵傷 ×0.85：避免恐怖狀態傷害凍結 + 鏡像牌組造成批次「假死結」。

結果（可引用數字）

校準項目 調整前 調整後 備註
港灣普通（入門 30 張牌組）自動 AI 勝率 0%（舊敵池含 SSR） ~15.5%（200 局） 自動 AI 低於真人；企劃區間 0.62～0.70 敵傷倍率
M-1-2 段考 A（50 局 quick sim） 批次曾中途卡住 50/50 局跑完，平均 4.3 回合 段考通過率 0% → 提示自動出牌 AI 與「觸發三戰技」目標 gap

證據
- Assets/SimResults/harbor_normal_tutorial_deck_winrate.md
- Assets/SimResults/m12_phase_a_exam_winrate.md
- 選單：Tools/Harbor/Win Rate Sim…、Tools/M-1-2/Win Rate Sim…
- MCP／自動化：DevAutomation.StartM12PhaseAWinRateSim()

4. 卡面美術與資源引用容易「有圖但遊戲裡看不到」

問題
組牌格要 DeckThumb、商店／詳情要 CardArt，混用或漏綁會導致白圖；BGM、教練表情、UI 圖分散各資料夾，pull 新資源後常忘記刷新 Library。

方案
- 美術分工定案：Assets/UI/DeckThumb/ vs Assets/UI/CardArt/，企劃與程式同一套語意（GAMEPLAY_AND_RULES.md §3.1）。
- Editor 管線：CardArtworkAutoBinder Rescan → CardArtLibraryPopulator；UnityLibraryRefreshBatch 一鍵刷新 Audio／Font／Sprite／CardArt。
- ScriptableObject Library：Runtime 從 Resources/*Library.asset 取引用，避免場景硬拖漏連。

結果
- 新增卡面 PNG 後有固定 SOP（Rescan → Refresh Library），減少「Editor 有圖、手機 APK 沒圖」。
- Agent／CI 可跑 PowerShell + batchmode（unity-library-refresh skill）。

證據
- Assets/Editor/CardArtworkAutoBinder.cs、UnityLibraryRefreshBatch.cs
- Docs/CURSOR_SKILLS_MANUAL.md §unity-library-refresh

5. 多場景、多槽存檔、全域 UI — 程式容易變成「改一處壞十處」

問題
大廳、組牌、對戰、設定、大地圖各自演化，GlobalNavRuntime 曾膨脹到千行級；牌組名稱污染、存檔槽錯寫等 bug 難追。

方案
- 場景流程與存檔單一真相：PlayerData + StoryProgressNodeDatabase.json + TutorialProgressState 旗標分層。
- Partial class 重構：GlobalNavRuntime 拆成 Navigation／Vault／UiBuild 等檔，掃描從 Bad → Fair（CODE_QUALITY_SCAN_REPORT.md）。
- Editor 測試與存檔工具：Player Save 備份還原、牌組名稱污染修復選單、Bug scenario 場景。
- Play Mode 自動化 API：DevAutomation.cs + Unity MCP execute_code，長流程用協程而非單帧狂點。

結果
- 回歸主線（1-1 入門 → 港灣首通 → 1-2 段考）可用腳本重跑，不必每次手動點 20 分鐘。
- 新功能（M-1-2 恐怖狀態、段考結算）可掛在同一 BattleSimulationManager partial 擴充，不另開一套戰鬥核心。

證據
- ARCHITECTURE_OVERVIEW.md
- Assets/Scripts/DevAutomation.cs、Docs/MCP_USAGE_EXAMPLES.md
- Docs/DECK_SLOT_NAME_BUG_CHECKLIST.md

6. 同一張牌資訊過載 — 用「熟練度分階」代替一次塞滿規則

問題
怪物戰技文案長，若一開始全顯示，卡面與新手認知負荷過高；若完全不顯示，又失去成長感。

方案
- A / B / C 三階揭露：A 只有攻血 → B 一行摘要 → C 完整規則（CARD_PROFICIENCY_GDD.md）。
- 御三家（國王／王后／民兵）預設 C，作為「解鎖後長什麼樣」的對照樣本。
- 結算浮層播放熟練度條，讓成長可見。

結果
- 第一場只需會出牌；中後期同一張牌「長出新招」形成長線動機，與港灣重複練習 loop 呼應。

證據
- CARD_PROFICIENCY_GDD.md、卡牌技能階段式揭露.md
- 畫面：Docs/pitch_pillar02_proficiency.png

7. Android 實機與 Editor 行為不一致

問題
建置路徑含中文會失敗；Game 視窗比例與手機 Safe Area 不同，按鈕被裁切或影片層擋點擊；商店開包在真機常卡住。

方案
- 專案路徑 ASCII 定案：E:\School\Grade_5_2\card-game（README 明訂，避開 2024畢業專題 舊路徑）。
- Canvas 1920×1080 基準 + 各場景 CanvasScaler 策略；商店／開包關閉全屏 RawImage raycast、以播放進度作為完成備援。
- Settings 顯示比例 JSON：BattleCardTuningPresets.json + PlayerPrefs，讓不同螢幕可驗證同一套參數對照表。

結果
- APK 可穩定從 login → hall → 主線試玩；設定頁可切「預設一／對照組」驗證 UI 調校是否生效。

證據
- README.md Android 小節、BattleCardTuningPresetLibrary
- DevAutomation.ApplyBattleCardTuningPreset1ToOpenScene()（MCP 可呼叫，避免錯誤 MenuItem 子路徑）

玩家實際會走的一條路

登入選槽 → 遊戲進度（Story progress）→ 1-1 劇情 → 入門教學戰
    → 結算（金幣・熟練度）→ Buildbeck 組牌 → 港灣訓練場（選難度）
    → 解鎖 1-2 → 段考 A（御三家）→ 段考 B（教練實戰）→ 持續擴充中

30 秒快速開始
1. 安裝 APK，橫向握持。
2. 登入 → 新建或選存檔 → 遊戲進度。
3. 點 1-1 港灣訓練場 → 進入關卡 → 跟劇情進入教學戰。
4. 畢業後再挑戰港灣實戰；牌組在 Buildbeck 編輯。
