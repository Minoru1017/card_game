> 測試場景：`Assets/Scenes/Bug handling scenarios.unity`  
> 最後更新：2026-06-21

## 一、無 Bug 狀態定義（驗收標準）

以下為**通過驗收**時應成立的行為。任一項不符即視為仍有 Bug。

### 1.1 槽位與預設名稱

| 項目 | 預期 |
|------|------|
| 牌組槽數量 | **5 槽**（索引 0～4） |
| 未自訂時的顯示名稱 | **牌組1、牌組2、牌組3、牌組4、牌組5** |
| 預設名稱是否寫入存檔 | **否**（僅 UI fallback；CSV `deck_slot_name` 該槽應為**空白**，直到玩家自訂並確定） |

### 1.2 重新命名（Buildbeck「確定」）

| 步驟 | 預期 |
|------|------|
| 玩家輸入新名稱並按下 **「確定」** | 畫面上**目前牌組名稱**（分頁標籤、名稱列、相關 UI）**立即**顯示新名稱 |
| 存檔 | 玩家資料庫（`playerdata.csv` 之 `deck_slot_name`）中，該玩家槽、該牌組槽的**舊名稱被新名稱覆寫** |
| 跨場景 | 切換至其他場景再返回（或重開 Buildbeck），**仍顯示並載入新名稱**，不回到舊名稱或錯槽名稱 |
| 玩家資訊面板 | 「牌組」摘要與實際自訂名稱一致（存檔後刷新） |

### 1.3 玩家槽隔離（3 槽）

| 項目 | 預期 |
|------|------|
| 槽 1 / 2 / 3 的 5 個牌組名稱 | **各自獨立**；在槽 A 改名不得覆寫槽 B 的 `deck_slot_name` |
| 切換 active 玩家槽 | 記憶體與 CSV `active_slot` 一致後，載入**該槽**的名稱，而非上一槽殘留 |

## 二、名稱會被覆寫／還原的三種流程（規格）

以下為**設計上允許**改變「目前生效名稱」的三種情況。測試時應分項驗證。

### 流程 1：輸入後未按「確定」

| 項目 | 說明 |
|------|------|
| 操作 | 開啟重新命名、輸入文字，**關閉或取消，不按「確定」** |
| 預期 | **不寫入**存檔；畫面與資料庫維持**改名前**的名稱（自訂名或預設「牌組N」） |
| 驗收 | 重載場景 / `LoadPlayerData` 後名稱不變 |

### 流程 2：再次輸入新名稱並按「確定」

| 項目 | 說明 |
|------|------|
| 操作 | 已有自訂名稱（或曾自訂過），再次開啟重新命名、輸入**另一個**名稱並按 **「確定」** |
| 預期 | 畫面**立即**顯示最新名稱；資料庫**以新名稱覆寫舊自訂名稱** |
| 驗收 | `GetRawName` / CSV 該列僅保留最後一次確定的字串 |

### 流程 3：牌組遭解散

| 項目 | 說明 |
|------|------|
| 操作 | 對該牌組執行**解散／清空牌組**（Buildbeck 解散牌組流程） |
| 預期 | 該牌組槽名稱**還原為預設**「牌組N」（N = 槽序 1～5）；存檔中該槽 `deck_slot_name` 應清空或等效於未自訂 |
| 驗收 | UI 顯示「牌組N」；重載後仍為預設，而非解散前的自訂名 |

## 三、Bug 待解決清單

勾選 `[ ]` 表示尚未修復；`[x]` 表示已修復並依「二、無 Bug 狀態」複測通過。

### 3.1 顯示與綁定

- [x] **Buildbeck 名稱列未更新**：按「確定」後主畫面名稱仍為舊字（曾發生：`CurrentDeckDisplayName` 綁到錯誤節點，如 `ready` 按鈕子物件）
- [x] **玩家資訊面板牌組摘要未更新**：改名後「持有的牌組」仍顯示舊摘要（`profile_decks` / 未呼叫 sync）
- [x] **Bug 測試場景按鈕直排字**：操作按鈕 `RectTransform` 寬度過窄導致標籤垂直顯示（UI 排版，非資料 Bug）

### 3.2 存檔與載入

- [x] **預設名稱被寫死進 CSV**：未自訂時存檔寫入「牌組1～5」，導致無法與「真正的自訂名」區分（應只存 raw 空白 + UI fallback）
- [x] **玩家槽錯位寫入**：`active_slot` 與記憶體不一致時，A 槽自訂名被寫入 B 槽的 `deck_slot_name`（曾見 slot 2 / 3 CSV 同名）
- [x] **切換玩家槽未重載**：僅改 CSV `active_slot` 未 `LoadPlayerData`，後續 Save / Profile sync 污染他槽
- [ ] **跨場景後名稱丟失或還原**：確定改名並存檔後，切場景再回來仍變回舊名或預設名（需在 Buildbeck 實測）

### 3.3 規格流程（第二節三點）

- [x] **流程 1**：輸入未按確定 → 確認不寫入（Bug 場景「捨棄輸入」+ 未 Save 驗證）
- [x] **流程 2**：二次確定改名 → 確認新名稱覆寫舊自訂名（Bug 場景「確定（流程2）」+ EditMode）
- [x] **流程 3**：解散牌組 → 確認還原「牌組N」且存檔一致（`PerformResetDeckForRebuild` + Bug 場景「解散還原」）

### 3.4 資料異常（已知現象）

- [x] **存檔亂碼／污染字串**：`LoadPlayerData` 前自動執行 `RepairPersistedDeckSlotNamePollutionIfNeeded`；Bug 場景 / Tools 選單可手動清理

## 四、建議測試步驟（最小路徑）

1. 開啟 **Bug handling scenarios** 或 **Buildbeck**，確認 5 槽預設顯示為牌組1～5。  
2. 槽 1 牌組 1 改名「測試A」→ **確定** → 畫面 + Console `DescribeInMemory` / `DescribeDiskRowsForPlayerSlot(1)` 一致。  
3. 切換玩家槽 2，改名「測試B」→ 確定 → 切回槽 1，仍為「測試A」。  
4. 流程 1：輸入「未保存」→ 按 **捨棄輸入（流程1）** → 再 **重載** → 名稱不變。  
5. 流程 2：再改名「測試A2」→ 按 **確定（流程2）** → 僅保留 A2。  
6. 流程 3：先 **對齊 active 槽** → 按 **解散還原（流程3）** → 顯示還原牌組N → **重載** 仍為預設。  
7. 進入其他場景再回 Buildbeck → 名稱仍正確。
